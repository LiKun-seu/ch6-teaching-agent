# 初始难度标注与题库契约

全部 150 题的初始难度与逐题判断理由保存在 `src/content/question-meta.json`。按题干、选项和完成题目所需的认知步骤逐题阅读标注，不使用题型、ID 取模、随机数或答案置信度分级。调整入口就是这份数据文件。

| 难度 | 口径 | 全题库 | 当前可抽题 |
| --- | --- | ---: | ---: |
| 简单 | 直接识记单个事实、概念、定义或判断 | 47 | 36 |
| 中等 | 区分相近概念，完成一步条件判断或公式应用 | 79 | 41 |
| 困难 | 组合多个条件，比较适用边界，或多步推理 | 24 | 14 |
| 合计 | | 150 | 91 |

例如 SC-03 识记抗扭配筋为简单；SC-01 从中和轴判断受压钢筋屈服为中等；SC-27 同时核对拉压钢筋两个屈服边界为困难。选择、判断、填空均按认知要求分级。部分未复核、资料缺损题仍按其预期考查动作标注，理由中如实注明资料问题；难度标注不代表题目复核通过。原题干、答案、ID、verified 都没有修改。

## 可用题的实测更正

远端 issue 中的 115 是 `verified === true` 的数量，不是结构有效且不泄露答案的可抽数量。当前严格可用的为 **91 题**（选择 44、判断 44、填空 3）。全部 115 道已复核题都有难度；其中 24 道依下面规则排除，不为满足数量静默重建选项或猜测原题。

- 22 道已复核选择题缺少选项、选项合并、答案不在有效选项中或含公式占位：SC-20、21、22、25、26、28、29、30、39、40、41、42、63、64、65、67、69、70、71、72、73、74。
- TF-24 题干条件仍为「待补」。
- TF-29 题干括号已填「×」，交卷前原样显示会泄露标准判定，故排除。

`[推断]` 标记本身不影响可用性；例如 SC-27、TF-14、TF-16 条件和结构完整，仍可使用。修复缺损题须经过明确的内容复核，不能由抽题函数暗中补齐。

## 共用纯模块

`src/lib/question-catalog.ts` 导出 `QuestionDifficulty`、`CatalogQuestion`、`getQuestionCatalog(): readonly CatalogQuestion[]` 和 `isUsableQuestion(question: Question): boolean`。后者独立检查已复核、标准答案、题干及题型结构，不依据难度。模块只依赖原题库、元数据及现有纯判题规范，不依赖 React、浏览器存储或 Node 写入。

catalog 初始化显式校验重复 ID、难度缺漏与悬空 ID。课堂服务端可以读取完整 catalog；给学生的接口只能挑选公开题干、选项等字段，不能把含标准答案和解析的 catalog 原样响应。自测按此门禁过滤后无放回随机抽样，不修改 catalog 或原题库顺序。
